# Domain Docs

## Layout

Single-context: `CONTEXT.md` and `docs/adr/` at the repo root.

## Before exploring

Read root `CONTEXT.md` and ADRs relevant to the work.

If these files are absent, proceed silently. Domain-modeling
creates them as terms and decisions are resolved.

## Vocabulary

Use the domain terms defined in `CONTEXT.md` in issues,
proposals, hypotheses, and tests.

If a needed term is missing, reconsider whether it belongs
or note the gap for domain-modeling.

## ADR conflicts

Explicitly identify any existing ADR contradicted by a proposal,
including the decision and reason for reopening it.
